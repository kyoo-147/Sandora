## Outcome

Sandora has one verified CEO identity, a progressive-disclosure Herdr operating
guide, evidence-backed runtime/model routing, and project-native project
memory. Additional agents are peer main-agent sessions created only through
Herdr.

## Context and authority

- `identity.md` and `AGENTS.md` define CEO identity and delegation boundaries.
- `docs/operations/HERDR.md` defines local coordination procedure.
- `docs/operations/MODEL_ROUTING.md` records measured routing guidance.
- Installed CLI help, live catalogs, official vendor documentation, cited
  upstream files, and observed validation override stale snapshots.

## Workstreams and dependencies

- `herdr_research`: inspect installed Herdr and official documentation; return
  progressive-disclosure recommendations and exact command evidence.
- `model_research`: inspect GPT-5.6, CMDC, and AGY from official/live sources;
  distinguish verified facts, catalog descriptions, and unbenchmarked claims.
- `project_memory_review`: independently review Sandora's project-memory
  structure; identify omissions, conflicts, and validation needs.
- `ceo`: reconcile lane claims, edit repository truth, validate effective
  configuration, and return the executive result.

All lanes are read-only. Each must stop after producing a bounded evidence-backed
report; no agent may spawn subagents or alter global/project state.

## Approval gates and risks

- Owner approval remains required for destructive actions, external writes,
  credentials, production changes, financial commitments, governance changes,
  or material scope expansion.
- Runtime catalogs change quickly; dated snapshots must not be treated as live
  authority.
- Agent reports remain claims until CEO inspects cited local or official evidence.
